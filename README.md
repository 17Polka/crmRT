## 📤 Как запушить проект на GitHub (Git Push)

В репозитории уже настроен `.gitignore`, удалены все временные файлы, архивы и бинарники. 

Выполните следующие команды в терминале PowerShell / Git Bash из корневой папки проекта (`c:\mos\crmRT`):

### Шаг 1. Добавить все файлы в индекс:
```bash
git add .
```

### Шаг 2. Создать коммит с описанием изменений:
```bash
git commit -m "feat: unified FastAPI backend, RBAC, persistent DB, reports and mobile UI"
```

### Шаг 3. Отправить изменения в удалённый репозиторий:
Текущая рабочая ветка — `backend`. Для отправки в неё:
```bash
git push origin backend
```

> [!TIP]
> **Если требуется слить изменения в основную ветку `main`:**
> ```bash
> git checkout main
> git merge backend
> git push origin main
> git checkout backend
> ```

## 🌐 Как запустить сервер для внешних пользователей (вне одной сети)

> [!NOTE]
> **Почему не используется запуск через один `.bat` файл:**
> Запуск через один `.bat`-скрипт с встроенными анонимными туннелями нестабилен: брандмауэр Windows Defender блокирует порты, анонимные туннели без учетной записи периодически разрывают связь, а главное — браузеры показывают пугающие экраны безопасности (*«Caution / Serveo Warning»*).
> Ниже приведены проверенные, профессиональные способы предоставить доступ другим пользователям.

---

### Вариант 1. Бесплатный облачный деплой на Render.com (Рекомендуется, 3 минуты)
*Это промышленный стандарт: сайт разворачивается в облаке, получает официальный HTTPS-домен с доверенным сертификатом, работает 24/7 (даже когда ваш ноутбук выключен) и открывается у любого человека в мире без каких-либо предупреждений.*

1. **Запушьте проект в GitHub** (см. раздел выше).
2. **Зайдите на сайт [Render.com](https://render.com/)** (авторизация через GitHub в 1 клик, бесплатно).
3. Нажмите **New +** → **Web Service** → выберите ваш репозиторий `crmRT`.
4. Заполните настройки сервиса:
   - **Name**: `crm-rostelecom` *(или любое удобное вам имя)*
   - **Region**: Frankfurt (EU)
   - **Branch**: `backend` *(или `main`)*
   - **Root Directory**: `backend`
   - **Runtime**: `Python 3`
   - **Build Command**: `pip install -r requirements.txt && python seed.py`
   - **Start Command**: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Нажмите кнопку **Create Web Service**.
6. Через 2-3 минуты сборка завершится и вы получите постоянный красивый адрес:
   👉 **`https://crm-rostelecom.onrender.com`**  
   *(Эту ссылку можно передавать жюри, вставлять в презентацию и открывать с любых мобильных устройств без ограничений)*.

---

### Вариант 2. Запуск на ноутбуке + официальный Ngrok (через интернет)
*Если вы хотите, чтобы сервер работал локально на вашем компьютере, но ссылка открывалась через интернет у любых людей в других сетях:*

1. **Запустите бэкенд на компьютере**:
   ```powershell
   cd backend
   python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. **Зарегистрируйтесь бесплатно на [ngrok.com](https://dashboard.ngrok.com/signup)** (30 секунд).
3. В личном кабинете скопируйте персональный токен и привяжите его (делается один раз):
   ```powershell
   ngrok config add-authtoken ВАШ_ТОКЕН
   ```
4. **Запустите туннель**:
   ```powershell
   ngrok http 8000
   ```
5. В окне терминала появится ссылка вида `https://xxxx.ngrok-free.app`. С привязанным аккаунтом она работает стабильно и открывается на любых внешних устройствах.

---

### Вариант 3. Быстрый туннель без регистрации (Pinggy) и почему он показывает экран «Caution»
*Если нужно запустить туннель без регистрации за 5 секунд через стандартный SSH:*
```powershell
ssh -R 80:localhost:8000 a.pinggy.io
```
> [!WARNING]
> **Почему появляется экран «Caution: Make sure you trust this website»?**
> Все бесплатные и анонимные туннельные сервисы (Pinggy, Serveo, Localtunnel) принудительно показывают промежуточную страницу защиты от фишинга. Это сделано специально, чтобы злоумышленники не использовали анонимные ссылки в мошеннических целях.
> **Что делать пользователю:** нажать кнопку **«Enter site»** (или *«Continue to Site»* в Serveo). После этого браузер ставит cookie и перенаправляет на саму CRM-систему, где все функции работают в обычном режиме.

---

### Вариант 4. Доступ с телефона в одной Wi-Fi сети (без интернета и сторонних сервисов)
*Если вы и тестирующие находитесь в одном помещении (подключены к одному роутеру Wi-Fi):*

1. **Узнайте локальный IP-адрес ноутбука**:
   ```powershell
   ipconfig
   ```
   Найдите строку `IPv4-адрес` у вашего Wi-Fi адаптера (например, `192.168.1.45` или `192.168.0.12`).
2. **Запустите сервер на `0.0.0.0`**:
   ```powershell
   cd backend
   python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
3. **Настройка брандмауэра Windows (Важно!)**:
   - По умолчанию Windows помечает домашний/офисный Wi-Fi как «Общедоступная сеть» (Public) и блокирует входящие подключения с телефонов.
   - Откройте **Параметры Windows** → **Сеть и интернет** → **Wi-Fi** → свойства вашей сети → выберите **«Частная сеть»** (Private).
4. На телефоне в браузере откройте:  
   👉 **`http://192.168.X.X:8000`** *(подставив ваш IP из п. 1)*.

## 💻 Локальный запуск на компьютере

### Способ 1. Запуск через Python (быстрый старт)

1. Откройте терминал в папке проекта и перейдите в каталог бэкенда:
   ```powershell
   cd backend
   ```
2. Установите зависимости проекта:
   ```powershell
   pip install -r requirements.txt
   ```
3. Инициализируйте базу данных начальными данными (10 пользователей, 16 вузов):
   ```powershell
   python seed.py
   ```
4. Запустите сервер:
   ```powershell
   python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```
5. Откройте в браузере:
   - **Веб-интерфейс CRM**: [http://localhost:8000](http://localhost:8000)
   - **Интерактивная документация Swagger API**: [http://localhost:8000/docs](http://localhost:8000/docs)

---

### Способ 2. Запуск через Docker Compose

Если на компьютере установлен Docker:
```bash
docker compose up --build
```
Поднимется изолированный контейнер с PostgreSQL и FastAPI-бэкендом на порту `8000`.

## 🚀 Ключевые возможности и соответствие ТЗ

### 1. Регламентный Workflow из 14 этапов
- Полная цепочка жизненного цикла взаимодействия от **«Поиска контактов ответственного в вузе»** до **«Контроля за исполнением каждого этапа»**.
- **Канбан-доска**: интерактивные карточки вузов, подсчет взаимодействий.
- **Переходы между этапами**: перевод вперед и возврат назад. При возврате назад комментарий с обоснованием причины **строго обязателен** (проверяется фронтендом и бэкендом).
- **Контроль сроков и зависших этапов**: автоматический расчет дней без обновления. Выделение проблемных взаимодействий:
  - `> 14 дней` — требуют внимания;
  - `> 21 день` — просрочено / зависло.
- **Настройка этапов**: Администратор может переименовывать регламентные шаги под новые стандарты обучения.

### 2. Каталоги и карточки ВУЗов
- Поля карточки по ТЗ:
  - Полное и краткое наименование, город, ИНН;
  - ИТ-направление и программа обучения;
  - Продукт и вендор (Ростелеком, Ростелеком-Солар);
  - Номер договора и статус передачи лицензий («Передано», «В процессе», «Не передано»);
  - Срок действия лицензии;
  - Закреплённый ответственный менеджер (КАМ);
  - Контакты представителей вуза и комментарии.
- **Импорт каталогов из Excel**: поддержка файлов `.xlsx` / `.xls` с автоматическим обновлением существующих записей и записью в журнал аудита.

### 3. Формирование и выгрузка отчётов
- Генерация за период (квартал, месяц, учебный год).
- **Динамический выбор колонок** через чекбоксы.
- Скачивание файлов:
  - **Excel (`.xlsx`)**: таблица через библиотеку `openpyxl`.
  - **PDF (`.pdf`)**: документ с таблицами через `reportlab`.
  - **Результирующий JSON (`.json`)**: итоговое состояние системы согласно **п. 6.4 ТЗ**.

### 4. Вложения и лицензии к этапам
- Прикрепление договоров, соглашений и лицензий к этапам и во вкладке «Документы» карточки вуза.
- Физическое сохранение файлов в папку `backend/uploads/` и запись метаданных в таблицу `attachments`.
- Защищённый эндпоинт скачивания файлов с проверкой прав доступа.
- Валидация форматов по ТЗ: `.png`, `.jpeg`, `.pdf`, `.zip`, `.gzip`, `.rar`, `.doc`, `.docx`, `.xls`, `.xlsx`.

### 5. Аналитика и графики (Chart.js)
- Столбчатая диаграмма распределения вузов по этапам workflow.
- **Экспорт диаграммы в PNG** в один клик.
- **Экспорт аналитического отчёта в PDF**.

### 6. Мобильная адаптивность
- Адаптивный дизайн под смартфоны (iOS / Android) и планшеты.
- Канбан-доска на мобильных устройствах превращается в **горизонтальную touch-карусель со свайпом пальцем** (`scroll-snap`), аналогично мобильным приложениям Jira/Trello.
- Всплывающие модальные окна в виде Bottom Sheet с поддержкой Safe Area Insets (вырезов экранов).

### 7. Внешние интеграции (LMS и CMS Laravel)
- API-эндпоинты (`/api/integrations/lms`, `/api/integrations/site`, `/api/integrations/sync`) для обмена данными в формате JSON с LMS ИТ Школы и веб-порталом на Laravel.

## 📡 API эндпоинты (Swagger)

Интерактивная документация Swagger UI доступна по адресу **`/docs`**.

### Основные группы эндпоинтов:
- **`POST /api/security/login`** — авторизация пользователя, получение JWT-токена.
- **`POST /api/security/logout`** — выход из системы, отзыв и блокировка токена.
- **`GET /api/security/users`** — список пользователей (Руководитель, Администратор).
- **`POST /api/security/users`** — создание нового сотрудника (Администратор).
- **`POST /api/security/users/{id}/block`** — блокировка учетной записи (152-ФЗ).
- **`GET /api/security/audit`** — журнал аудита событий безопасности (Руководитель, Администратор).
- **`GET /api/security/audit/export`** — выгрузка аудита в `.xlsx` (Администратор).
- **`GET /api/workflow/board`** — канбан-доска 14 этапов (изолирована по правам КАМ).
- **`POST /api/workflow/{id}/transition`** — смена этапа вуза с комментарием и файлом.
- **`POST /api/workflow/{id}/attachments`** — загрузка файла к этапу.
- **`GET /api/workflow/{id}/attachments/{att_id}/download`** — безопасное скачивание файла.
- **`GET /api/reports/generate`** — генерация отчета в форматах `xlsx`, `pdf`, `json`.
- **`POST /api/catalogs/import/universities`** — импорт каталога вузов из Excel.
- **`POST /api/integrations/sync`** — синхронизация с LMS и CMS Laravel.

## 🔒 Безопасность (152-ФЗ / ФСТЭК №117)

1. **Неизменяемый журнал аудита**:
   - Таблица `audit_logs` фиксирует все действия: авторизация, выход, смена ролей, перевод этапа, доступ к персональным данным, блокировка учетных записей.
   - Фиксируется дата и время, идентификатор пользователя, тип действия, IP-адрес и детали события.
2. **Изоляция прав доступа**:
   - Пользователь с ролью `manager` (КАМ) не имеет доступа к журналу аудита ни через интерфейс, ни через прямой вызов API (возвращается `403 Forbidden`).
3. **Отзыв токенов**:
   - При выходе из системы JWT-токен помещается в черный список (`blocked_tokens`) и немедленно перестает приниматься API.
4. **Блокировка пользователей**:
   - В соответствии с 152-ФЗ доступ заблокированного пользователя прерывается мгновенно.
